# MindVault v4.1 — LLM 백엔드 정책과 실험 어댑터

**Status:** Public policy decided [2026-07-23]

## 1. 공개판 정책

MindVault 공개판의 공식 기본값과 지원 대상은 로컬 Gemma 4 12B다.

- Codex CLI나 Claude Code가 설치돼 있어도 클라우드 모델을 자동 호출하지 않는다.
- 기존 설치자의 동작·프라이버시·구독 한도를 업그레이드가 임의로 바꾸지 않는다.
- Luna·Haiku 등 대체 LLM은 개인 fork의 비공식 커스터마이징으로 안내한다.
- 대체 모델의 구독 한도, 클라우드 전송, 호환성, 업데이트 유지보수 책임은 선택한
  사용자에게 있다.

## 2. 기본 런타임

| 작업 | 공식 백엔드 |
|---|---|
| SessionStart 요약 | Gemma |
| 세션 검색 재순위·요약 | Gemma |
| Stop/SessionEnd 기억 추출 | Gemma |
| Memory Compiler | Gemma |
| 별칭 생성 | Gemma |
| 모순 감지 | Gemma |
| UserPromptSubmit intent | 결정론적 규칙, Gemma 보강은 opt-in |
| 임베딩·hybrid recall | Arctic-ko + FTS5 |

설치기는 Gemma 모델과 `com.mindvault.gemma-mlx` launchd 서비스를 계속 제공한다.

## 3. Stop 안정화는 유지

LLM 선택과 무관하게 v4.1의 Stop 과부하 방지 구조는 유지한다.

- session별 20초 quiet-period debounce/coalesce
- persistent byte cursor 이후 delta와 3-message overlap만 처리
- 약 16,000자 단위 chunk
- 전역 single-flight
- 성공 응답(`[]` 포함) 이후에만 cursor와 멱등키 확정
- timeout·전송·parse 실패 시 cursor 보존

이 구조는 Gemma 기본판에서도 긴 세션과 turn-scoped Stop 중첩으로 인한 메모리 폭주를
막는 필수 안정화다.

## 4. Codex CLI 실험 어댑터

`src/llm_backend.py`에는 자동 추출용 Codex CLI 어댑터가 남아 있다.
`MV3_LLM_PROVIDER=codex_cli`를 명시한 경우에만 `gpt-5.6-luna`, reasoning `low`를
사용한다. 이는 추출 경로만 바꾸며 전체 MindVault 백엔드 전환을 의미하지 않는다.

어댑터 규약:

- ephemeral·ignore-user-config·read-only sandbox
- JSON output schema
- `MV3_HOOK_RECURSION_GUARD=1`
- timeout·parse 실패 시 `None`
- 민감정보가 redact된 입력은 Gemma로 로컬 라우팅

## 5. 전체 Luna·Haiku 전환

전체 전환 대상은 다음과 같다.

- `src/memory_extractor.py`
- `src/session_memory.py`
- `src/search.py`
- `src/memory_compiler.py`
- `src/alias_generator.py`
- `src/contradiction_detector.py`

공개판은 이 조합을 공식 지원하지 않는다. README의 복사 가능한 요청문을 Codex 또는
Claude Code에 전달해 별도 로컬 브랜치에서 수정하고, 전체 회귀와 실제 응답 smoke
test를 수행한다. FTS5·Arctic-ko·UserPromptSubmit hot path는 변경하지 않는다.

## 6. 검증 기준

- 기본 환경에서 wrapper가 `gemma`를 선택
- Codex 설치 유무가 기본 provider를 바꾸지 않음
- 명시적 `MV3_LLM_PROVIDER=codex_cli`만 추출 어댑터를 활성화
- Gemma installer·plist·runner 자산 보존
- 전체 테스트, shell syntax, install/uninstall 계약 통과
