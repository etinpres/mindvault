# MindVault v4.1 — LLM 백엔드 추상화 + 비동기 경로 모델 승격 (스펙 초안)

**Status:** Draft — 구현 플랜 아님 (플랜은 착수 시 별도 작성)
**관계:** v4 플랜(`docs/plans/2026-07-21-v4-multi-agent-memory.md`)과 독립 스프린트. 단 §6의 1단계(추상화 레이어)는 v4 Task P2 전에 선행하면 P2가 처음부터 새 인터페이스 위에 올라가 이득.

## 1. 배경 / 문제

MindVault의 모든 LLM 호출이 로컬 Gemma 4 12B(MLX-VLM, localhost:8080) 단일 의존이다. 운영에서 확인된 한계:

- **정확도** — 추출·모순감지 등 판단성 태스크에서 품질 한계 체감 (사용자 보고 [2026-07-21]).
- **콜드 지연** — 모델 콜드/경합 시 응답이 수 초로 늘어남. hot path intent 폴백이 이로 인해 400ms 예산을 넘겨 회수 skip을 유발했고, [2026-07-21] `MV3_GEMMA_INTENT` off로 조치됨 (`~/.zshenv`·`~/.zshrc` 주석 처리).
- **자원 경합** — 단일 MLX 서버를 MindVault·gemma-worker·기타 자동화가 공유.

## 2. 목표 / 비목표

**목표**
1. 비동기 LLM 경로 전체를 provider 추상화 뒤로 옮겨 **설정 변경만으로 모델 교체** 가능하게 한다.
2. 기본 provider를 클라우드 경량 모델(Haiku 4.5)로 승격하고, 판단성 태스크는 Sonnet 5 low effort로 선택 승급한다. Codex CLI 경로(luna 등)를 대등한 provider로 추가한다.
3. 프라이버시·오프라인 요건은 Gemma 로컬 경로를 **폴백·강제 로컬 모드로 존속**시켜 지킨다.

**비목표**
- hot path(회수 hook)에 LLM 도입 — 불변. rule-based intent만 유지.
- 회수 게이트(TOP_K·cosine) 튜닝.
- Gemma 서버 폐기 — 하지 않는다 (폴백 + 프라이버시 로컬 경로 + gemma-worker는 별개 존속).

## 3. 대상 호출부 (현행 Gemma 직호출)

- `src/memory_extractor.py` `call_gemma()` — 세션 추출 (v4 P2의 Codex 추출도 동일 경로)
- `src/memory_compiler.py` — 메모리 컴파일
- `src/search.py` — 검색 보조 변환
- `src/contradiction_detector.py` — Layer 5 모순감지 (4-way)
- 그 외 구현 시 `grep -rn "localhost:8080\|call_gemma" src/` 전수 확인

## 4. 설계

### 4.1 추상화 레이어

`src/llm_backend.py`:

```python
def complete(task: str, prompt: str, *, max_tokens: int, temperature: float = 0.2) -> str | None:
    """task별 라우팅 설정에 따라 provider 선택·호출. 실패 시 폴백 체인 후 None."""
```

**Providers**
- `gemma` — 현행 HTTP 호출 이식 (top-level `"enable_thinking": False` 규약 유지). 동작 무변경.
- `claude_cli` — `claude -p --model <id>` 헤드리스 (Max 구독 → 한계 내 추가 비용 0). 기본 `claude-haiku-4-5-20251001`, 승급 `claude-sonnet-5` + low effort. 프로세스 기동 2~5초는 비동기 경로라 허용.
- `codex_cli` — `codex exec` 기반 (luna 등 모델 지정). **Codex가 구현·벤치 담당.**
- (옵션) `anthropic_api` — 직접 API. 구독 rate 이슈가 실측되면만 추가 (YAGNI).

### 4.2 라우팅 설정

`~/.claude/mindvault-v3/llm_backend.json`:

```json
{
  "extraction":    {"provider": "claude_cli", "model": "claude-haiku-4-5-20251001", "fallback": "gemma"},
  "compile":       {"provider": "claude_cli", "model": "claude-haiku-4-5-20251001", "fallback": "gemma"},
  "contradiction": {"provider": "claude_cli", "model": "claude-sonnet-5", "effort": "low", "fallback": "gemma"},
  "_default":      {"provider": "gemma"}
}
```

설정 파일 부재·미설정 task = `gemma` → **배포 즉시엔 동작 무변경**, 점진 전환.

### 4.3 프라이버시 게이트 (사용자 결정 필요 — Open Question ①)

- 클라우드 전송 전 기존 `redact()` 적용 필수.
- `MV3_PRIVACY=local` env → 전 태스크 gemma 강제 (원클릭 로컬 회귀).
- 민감 패턴(비밀번호·API 키·계좌·주민번호 regex) 감지된 입력은 해당 건만 gemma 폴백.

### 4.4 실패 처리 (silent failure 금지)

클라우드 실패(타임아웃·rate limit·오프라인) → gemma 자동 폴백 → 그것도 실패 시 현행과 동일한 skip. 각 단계는 debug.log에 `llm-backend: <task> <provider> fail=<사유> → fallback` 형식으로 기록. metrics.jsonl에 `{"kind": "llm_call", "task", "provider", "elapsed_ms", "ok"}` 계측 추가 (비용·품질 추적 근거).

## 5. 채택 게이트 — eval 선행

기존 `eval_runner`/`eval_gate` + 골든 샘플로 A/B 후 전환 (감이 아니라 수치로):

| 비교 | 담당 |
|---|---|
| Gemma vs Haiku 4.5 (extraction·compile) | Claude Code |
| Haiku vs Sonnet 5 low (contradiction) | Claude Code |
| luna / codex_cli 경로 | Codex |

**전환 조건(태스크별):** 골든셋 정확도 Gemma 동등 이상(목표 +10pp), 파싱 실패율 ≤ 현행 절반, p95 완료시간 ≤ 현행 Gemma p95. 미달 태스크는 gemma 유지 — 부분 전환 허용이 이 설계의 요점.
