# MindVault v4.1 — Luna 단일 LLM 백엔드

**상태**: 구현 완료 (2026-07-23)

## 1. 결정

MindVault의 생성형 LLM 작업을 Codex CLI의 `gpt-5.6-luna`, reasoning
`low`로 통합한다. Gemma 로컬 서버·모델·Python 가상환경은 운영 경로와
설치기에서 제거한다. Claude CLI도 사용하지 않는다.

오프라인 또는 Codex 사용 불가 상태에서는 MindVault의 로컬 검색·회수는 계속
동작하지만 해당 비동기 LLM 작업은 건너뛴다. 로컬 생성형 LLM 폴백은 두지 않는다.

## 2. 작업별 경로

| 작업 | 구현 | 호출 단위 |
|---|---|---|
| Stop/SessionEnd 추출 | `memory_extractor` → `llm_backend` | delta chunk당 1회 |
| Memory Compiler | `memory_compiler` → `llm_backend` | 컴파일당 1회 |
| SessionStart 요약 | `session_memory` → `llm_backend` | 캐시 miss당 1회 |
| 검색 별칭 | `alias_generator` → `llm_backend` | 변경 메모리당 1회 |
| 세션 검색 보조 | `search` → `llm_backend` | 후보 전체를 1회 batch |
| 모순 감지 | `contradiction_detector` → `llm_backend` | top-5 후보를 1회 batch |

UserPromptSubmit의 intent 분류는 지연과 false positive를 피하기 위해 규칙 기반으로
유지한다. Arctic-ko 임베딩과 FTS5도 로컬 경로를 유지한다.

Contextual Retrieval synopsis는 A/B에서 검색 이득이 없었으므로 LLM 호출을 폐기하고
결정론적 title fallback으로 대체한다.

## 3. 공통 실행 규약

`src/llm_backend.py`가 모든 Luna 호출을 담당한다.

- `codex exec --ephemeral --ignore-user-config --skip-git-repo-check`
- read-only sandbox와 임시 작업 디렉토리
- 작업별 JSON output schema
- 기본 모델 `gpt-5.6-luna`, 기본 effort `low`
- `MV3_HOOK_RECURSION_GUARD=1`로 nested hook 재귀 차단
- 작업별 timeout과 `metrics.jsonl`/`debug.log` 계측

호환성을 위해 일부 함수명에 `gemma`가 남아 있지만 모두 Luna 공통 백엔드로
위임하며 로컬 HTTP나 Gemma 런타임 의존은 없다.

## 4. 프라이버시와 실패 처리

- 기존 redaction을 먼저 적용한다.
- 민감정보 치환 마커가 남은 입력은 Codex로 보내지 않고 해당 작업을 skip한다.
- `MV3_PRIVACY=local`은 클라우드 추출을 비활성화한다.
- timeout, rate limit, 오프라인, schema 오류는 기록한 뒤 안전하게 skip한다.
- 실패 때문에 staged write나 hook 본 흐름을 막지 않는다.

## 5. 설치·업그레이드

신규 설치는 Arctic-ko 임베딩 서비스만 설치한다. 업그레이드는 다음 legacy Gemma
launchd job과 배포 runner를 정리한다.

- `com.mindvault.gemma-mlx`
- `com.yonghaekim.gemma-mlx`
- `com.yonghaekim.gemma-mlx-daily-restart`

사용자 모델 cache와 과거 venv는 자동 설치 범위 밖이므로 마이그레이션 시 명시적으로
확인 후 제거한다.
